# HITROO Website — Knowledge Transfer (KT)

Living record of **what we have built**. Update it at the end of every working session. Pairs with [ARCHITECTURE.md](ARCHITECTURE.md) (how it fits together), [CHANGELOG.md](CHANGELOG.md) (what changed) and [designs.md](designs.md) (the design language).

## What HITROO is
A technology company (headquartered in Chennai, India; clients worldwide) presented as **one foundation with four divisions** (since 2026-10-24; the site never calls them "wings"): **Software** (our own products — not named until the owner gives real ones — custom software, mobile and desktop apps, managed services), **Automation** (workflow automation, AI agents, document processing, integrations), **AI** (custom and in-house models, private LLMs, vision systems) and **Creatives** (launched 2026-10: social media done for you — we create and post the content, analyse which posts perform best, and the client sees every post and its results in their dashboard). It supports clients after launch through the HITROO app (24h first response, 48h typical resolution). Contact: info@hitroo.com · +91 7550000805.

## Stack & ops
- **Next.js 13 App Router**, TypeScript, Tailwind; shadcn/ui primitives remain available. Marketing pages are **server components** with small client islands.
- **Hosting:** Vercel, live at `www.hitroo.com` since 2026-09-25 (`hitroo.com` redirects there); functions in `sin1` (see `vercel.json`); `next/image` optimization on. Pushing to `main` deploys to production. `netlify.toml` was removed on 2026-09-26.
- **Folders:** `Hitroo_internal_Apps/hitroo/` holds `hitroo_landing` (this site) and `hitroo_admin_page` (the admin); later internal apps go there too.
- **Database:** shared Postgres on Fly.io, app `hitroo-db` (PostgreSQL 18, region `sin`, public TLS endpoint `hitroo-db.fly.dev:5432`). Database `hitroo`: schema `web` for this site (role `web_app`, write-only plus reading posts) and the admin (role `admin_app`), schema `internal` for internal apps (role `internal_app`). This repo's `db/` holds the schema for all of them. Credentials: `Hitroo_internal_Apps/_secrets/hitroo-db.env`. Details: [ARCHITECTURE.md](ARCHITECTURE.md).
- **Commands:** `npm install` (no flags), `npm run typecheck`, `npm run lint`, `npm test` (50 node:test tests), `npm run db:migrate`, `npm run db:seed-posts`, `npm run media:upload`, `npm run content:seed`, `npm run indexnow` (after production deploys).
- **Page content and media (since 2026-10-25):** the copy of every marketing page except the legal pages, brand page and site map lives in `web.content` (22 keys: `company`, `home`, `quote`, `founder`, `divisions`, `showcase`, `services`, `audience`, `engagements`, `promises`, `steps`, `faq:general`, `division:*`, `page:*`, `video:creatives`), edited in the admin; editable images and the Creatives video live in Tigris (`hitroo-media`) with a `web.media` row each. The site reads them with `getContent()` (cached 5 min, refreshed at once by the admin's `/api/revalidate` call) and falls back to the built-in copy in `lib/` whenever the database can't be read. Seeded on 2026-10-25 from the built-in copy: 22 keys, 16 media rows (7 division photos, 2 portraits, 6 reels, the video with its poster).
- **Forms:** `LeadForm` → `/api/lead`, `CareersForm` → `/api/careers`. Both store to Postgres first, then email; per-visitor rate limits, email caps, honeypot, timing and optional Turnstile ([docs/contact-form-protection.md](docs/contact-form-protection.md)). `.env.local` has real SMTP credentials — test with `GMAIL_USER= GMAIL_APP_PASSWORD= npx next start` (stores without emailing) or via the honeypot (validated, then discarded), and delete test rows afterwards.

## Site structure
- `app/(warm)/layout.tsx` wraps every marketing page in `WarmShell`: skip link, `WarmHeader`, `<main id="main">`, `WarmFooter`, Analytics, CookieConsent (and the duotone filter for post covers). Design rules: [designs.md](designs.md).
- Every page except home opens with its name in still glass (`PageIntro`); every section has a caption, a plain heading and at most one line.
- `/` Home: live glass "hitroo" hero → the four divisions as large cards that slide sideways as you scroll (pinned on desktop) → How we deliver (four glass-numbered stages) → Who you'll work with (Rohit) → What are you looking for? (need picker) → recent articles → questions → contact panel and form.
- Divisions: `/software`, `/automation`, `/ai`, `/creatives` (one template, `components/warm/DivisionPage.tsx`, content in `division:<slug>`, built-in copy in `lib/division-pages.ts`): glass word → when to call us (three signs) → what we build (capability explorer) → one workflow start to finish and who does what (Automation, AI, Creatives) → standards (dark card) → process → ways to engage → questions → the other divisions → closing call to action.
- `/services` ("What we do": the problem → division map, each division's offers beside its glass numeral, who we work with, ways to engage, process, promises, questions) and `/services/[slug]` (glass word → the problem → what's included → three stages → what changes → who it's for → ways to engage → questions → more from the division); each service belongs to a division (`division` in `services`).
- `/insights` (latest articles, blog posts and news), `/articles`, `/blog`, `/articles/[slug]`, `/blog/[slug]`, `/news` (newsroom: news, press card with About HITROO and the brand kit), `/news/[slug]` — content from `web.posts`, managed in the admin app. Old `/news/<numeric id>` links still redirect to `/blog`.
- `/about` (why we started → the four divisions → what we believe → Rohit → how we work → promises → where we are → our view on AI → explore), `/research`, `/support`, `/careers` (role picker + application), `/contact` (contact panel and form → what happens next → questions), `/ai-perspective` ("Is AI a threat to HITROO?"), `/brand` (wordmark, glass, colours, type, rules, downloads and the kit zip), `/privacy`, `/cookies`, `/terms`, `/accessibility`, `/security` (+ `/.well-known/security.txt`), `/site-map`, `app/not-found.tsx` (glass "404").
- **Admin:** a separate app, `../hitroo_admin_page`, live at https://admin.hitroo.com — analytics (visits, clicks, reads, world map, sources, audience, hours), leads and applications (status, notes, search, résumés), posts. One owner password, kept in `_secrets/hitroo-admin.env`.
- API: `/api/lead`, `/api/careers`, `/api/track`, `/api/consent`, `/api/revalidate` (for the admin), `/api/indexnow` (Vercel Cron, daily 09:10 IST: pushes the day's new posts to IndexNow).
- Discovery: `/sitemap.xml`, `/robots.txt`, `/llms.txt`, `/llms-full.txt`, `/feed.xml` (RSS of all posts, linked from every page), IndexNow key file in `public/`.
- Questions (FAQPage data): every service page and `/services` show short questions built from site facts; posts get FAQ data from their `## Questions` section.

## Data we collect
- Enquiries and job applications (with resumes) in `web.leads` / `web.job_applications`.
- Page views in `web.page_views`: anonymous by default (path, referrer host, UTM, country/region/city from Vercel's edge, device/browser/OS, language, a random visit id held only in the page's memory); visitor and session IDs only after cookie consent. No IP addresses are stored.
- Clicks and engagement in `web.events`: link/button text and target (no query strings), visible seconds and furthest scroll per page view. A post counts as read at 75% of the article.
- Cookie decisions in `web.consents` (policy version `2026-09`). The policy text is `/privacy` and `/cookies` — have them reviewed by a lawyer before launch (it commits to 24-month analytics retention and 30-day responses to data requests).

## Key decisions
- **Theme (2026-10-24, round 8; replaces corporate white):** modelled on weichie.com — its type, colour and layout — at the owner's request: warm paper page, Plus Jakarta Sans headlines, Fustat text, one ember accent, white and frosted-glass cards, one dark card per page. Owner rules: one background colour (no section switching), symmetric equal cards, no shadows, no glows, no "newbie" copy or filler like "since 2024", glass across every page, live WebGL only in the home hero (still images elsewhere, so nothing stutters). Rejected on the way: Krida-style black/lime glass, a laptop story hero, a white studio with a pink-to-blue gradient through fluted glass (round 7), EB Garamond headlines.
- **Division pages (2026-10-24):** built from a study of the best agencies per vertical (Thoughtworks, Netguru, Work & Co; XRay.Tech, Genpact, Invisible; Faculty, Fractal, Landing AI; We Are Social, Born Social, SocialChain). Software was approved first, then the template went to all four. Facts the owner confirmed: clients own the code and models, no client data is retained, automation runs on HITROO's own platform, every engagement starts with a free call, Creatives is done for you with results in the client's dashboard.
- **Writing:** professional, creative and innovative at once — short, confident statements (one or two lines, the second in a quieter tone), concrete outcomes, no jargon, no invented clients or numbers.
- **Copy:** minimal and business-first; "Why HITROO" is one two-line statement, not a list of reasons. No careers promotion on the home page; no "Chennai" in marketing copy.
- **Logo (2026-10-24):** the rings were dropped. The logo is now the wordmark "hitroo" (Plus Jakarta Sans ExtraBold, lowercase) with "hi" in Ember, chosen by the owner from several wordmark and hand-drawn concepts; the app icon and favicons are the "hi" on paper. The glass wordmark is the hero and a brand asset. Before launch, file "HITROO" (word) in classes 9 and 42; use ™ until registered.
- **Database:** unmanaged Fly Postgres (we own backups and upgrades) reusing the slot of the destroyed `decern-hitroo` server; public TLS endpoint so Vercel can reach it; least-privilege roles per consumer.
- **Analytics:** first-party and privacy-first (no Google Analytics, no third-party cookies). A visit is one page load and the pages it navigates to; a reload starts a new visit.
- **Admin as its own app:** only the owner uses it (one password, no accounts). The website's database role cannot read leads, résumés or analytics — if the public site were ever compromised, nobody's details could be read through it.
- **Products removed** earlier (Capsona, Attyn, Belecure, Mockello, AI Marketing Agent) — don't reintroduce.
- **Content in the database, media in Tigris (2026-10-25):** so the owner edits copy and pictures in the admin without a deploy. Uploaded images are pre-sized WebP (480/960/1600/2400 px) served straight from storage, so they use none of Vercel's 5,000 monthly image transformations. Tigris alone answers over HTTP/1.1 in about 0.3–0.45 s per image from India, so images load through `/media/img/*`, a rewrite to the bucket cached on Vercel's CDN for a year (about 0.06 s once cached; HIT verified in production on 2026-10-25). Only requests without a `Range` header are cached: Vercel's CDN stores a ranged (206) response as the whole file and serves it to everyone, which broke the video on its first deploy. The video therefore streams straight from Tigris.
- **Images in `public/` stay on Vercel's image optimization** (AVIF from `/_next/image`). Cloudinary was tried on 2026-09-26 and dropped: on its Free plan `f_auto` never serves AVIF (WebP to Chrome, JPEG XL/PNG to Safari), so the home page's images would have gone from 511 KB to 1,047 KB on desktop and from 894 KB to 1,276 KB on iPhone. Revisit only on a paid plan whose `f_auto` includes AVIF.
- **Quotes:** a public figure's exact words with the source linked, recent and positive (the owner found "Software is eating the world" negative and dated). A photo only if it is freely licensed for commercial use (CC BY, CC0 or public domain, e.g. from Wikimedia Commons) with the credit shown under it — never a press photo and never a generated likeness. Nothing on the page may suggest they endorse HITROO. The words must make the case for hiring HITROO: Sundar Pichai's "every employee in every organization can become a builder" was dropped because it argues the opposite.
- **Imagery (2026-10-24):** the earlier photo sets read as AI-made, so photography now starts from references: per division, the most creative players on Awwwards, Dribbble and Behance are studied and their direction recreated in our style with Codex (camera, lens, light and film named in every brief). The owner reviews every image before it is used. Post covers keep their database paths and render in warm monochrome (`.duotone-warm`).

## ⚠️ Gotchas
- **Content: the database wins.** Once a key is in `web.content`, editing its built-in copy in `lib/` changes nothing on the site (it is only the fallback). Edit in the admin, or run `npm run content:seed -- --force` (overwrites every key, with history rows). Never rename a content key or change a shape without its schema (`lib/content-schema.ts`) and the admin.
- A saved key with the wrong shape (missing field, a division missing from `divisions`, duplicate service slugs) is ignored and the built-in copy shows instead; the server log says `content <key>: saved copy has the wrong shape`.
- `getContent()` serves its cache first: after an edit without a revalidate call, the old copy can show for up to five minutes, and the first request after expiry still gets it while it refreshes.
- In content, an image's `tone` is its average colour (`#rrggbb`); a division hero's text colour is `theme` (`light`/`dark`).
- Don't call `ReactDOM.preload` from a server component: the hint travels in the RSC payload, so Next's link prefetching downloads the preloaded images of every linked page. `Media` relies on `fetchPriority="high"` (React's server renderer adds the head preload itself).
- A section `layout.tsx` must render `{children}` — re-exporting the page as the layout swallows the page.
- A layout that sets a plain-string `title` stops the root title template for pages below it — put metadata in the page instead (see `/services`).
- `permanentRedirect()` inside ISR pages caches a 308 with no Location in Next 13.5 — use `next.config.js` redirects.
- `revalidatePath` refreshes pages but not route handlers (sitemap, llms.txt) in Next 13.5 — those use a 10-minute `revalidate`.
- Sticky headers show up mid-page in Playwright full-page screenshots; check sections with viewport screenshots instead.
- Don't set `referrer` in page metadata: Next 13.5 briefly writes other tags' values into it during client navigation (console errors). The `Referrer-Policy` header does the job.
- New `web` tables need explicit grants in their migration — `web_app` gets nothing by default (migration 003).
- Vercel never ran the old `netlify.toml` edge rate limits (the file is gone). Every limit lives in code and counts per server instance.
- VS Code checks the code with its own bundled TypeScript (6.x), newer than the project's 5.2.2. Keep both clean: `npx -y -p typescript@6 tsc -p . --noEmit` next to `npm run typecheck`. TypeScript 6 rejects `target: es5` (now `ES2017`), wants side-effect imports declared (`types/css.d.ts`) and rejects `Buffer` in `timingSafeEqual` with the old `@types/node` — compare secrets with `sameSecret()` in `lib/secret.ts`.
- Images on Vercel Hobby (free): 5,000 image transformations a month; past that, new images fail with 402 and show their alt text (cached ones keep working). The cache is keyed on each image's content, survives redeploys and lasts up to 31 days. So: the Creatives library (251 files) is served as static, display-sized WebPs with `unoptimized` and fingerprinted URLs (`?v=`, a one-year `immutable` header in `next.config.js`), using no transformations; only about 90 images (glass, division photos, post covers, the founder) go through the optimizer, which `npm run warm-images` pre-encodes after a deploy (about 210 variants; a redeploy with unchanged images costs nothing). Keep new bulk imagery static the same way. Check usage under Vercel → Usage → Image Optimization. AVIF is 25–45% smaller than WebP but 8–20× slower to encode the first time, so warming matters.
- Hobby is for non-commercial personal use under Vercel's fair-use terms; a business site belongs on Pro. Owner's decision (noted 2026-10-24).
- Glass words: the engine rounds corners by eroding and regrowing the letter shape, which erases strokes thinner than twice the radius (it took the crossbar out of "e" and split "a"). Words use `corner: 0.018`; keep the wordmark's 0.06 only for "hitroo".
- Vercel Functions reject request bodies over 4.5 MB (`413 FUNCTION_PAYLOAD_TOO_LARGE`, before our code runs). Uploads sent base64 in JSON must stay under about 3 MB; anything bigger needs a direct-to-storage upload.
